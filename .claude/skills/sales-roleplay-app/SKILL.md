# 営業ロールプレイングアプリ(顧客役攻略トレーニング)

医療機器営業向けの音声ロープレ練習Webアプリを新規構築、または既存実装を
拡張するためのスキル。**複数の顧客役シナリオを同時公開する**ことを前提に、
共有ロジックとシナリオ固有データを分離した構成を取る。

## リポジトリ構成(必ず守ること)

**完全クライアントサイドの静的Webアプリ**として実装する。
サーバー・APIキー・ログインは一切使わない。これにより
「URLをクリックするだけで誰でも使える」要件を満たす。

シナリオ(顧客役の職種・商材の組)ごとに**サブディレクトリを1つ**作り、
共有ロジック(engine.js/speech.js/app.js/style.css)はリポジトリ直下に
1組だけ置いて全シナリオで使い回す。GitHub Pages 1サイトの中で、
シナリオごとに別々のURL(`/<シナリオ名>/`)を持たせられる。

```
/
  style.css          共有: レイアウト・配色・チャットバブル等
  js/
    engine.js         共有: analyzeUtterance() / RoleAI クラス / scoreSession()
    speech.js         共有: SpeechIO(音声認識・合成ラッパー)
    app.js             共有: 画面遷移・タイマー・チャットUI・localStorage
  <シナリオ名>/         例: jimucho, bucho
    index.html          このシナリオのページ本文(タイトル・文言はここに直書き)
    js/data.js           このシナリオの商材・専門用語・台詞・フィードバック文言
```

`index.html` の `<script>`/`<link>` パスは、共有ファイルを `../style.css`
`../js/engine.js` `../js/speech.js` `../js/app.js` で参照し、
`data.js` だけは同じフォルダ内の `js/data.js` を参照する
(`<script src="js/data.js">` の後に共有スクリプトを読み込む順序を守る:
data.js → engine.js → speech.js → app.js)。

**新しいシナリオを追加する場合**は、既存シナリオのフォルダ(`index.html`
+ `js/data.js`)をコピーして商材・台詞を書き換えるだけでよい。
共有ロジックは一切変更しない。

## data.js が提供すべきグローバル(engine.js/speech.js/app.jsが参照)

| 定義 | 内容 |
|---|---|
| `ROLE_LABEL` | 顧客役の呼称(例:"事務長" / "部長")。UI文言・フィードバック文に差し込まれる |
| `VOICE_PREF` | `{ genderRegex, pitch }`。speech.jsの音声選択・ピッチに使用 |
| `PRODUCT` | 商材名・平易名・価格・強み・導入スケジュール |
| `JARGON` | 顧客が知らない専門用語のリスト(`{label, re}`) |
| `PLAIN_MARKERS` / `CONCLUSION_MARKERS` | 言い換え/結論先出しの検出パターン |
| `DISCOUNT_RE` / `DISCOUNT_REFUSAL_RE` | 値引き言及・拒否表現の検出パターン |
| `VALUE_CATEGORIES` | 価格以外の価値カテゴリ(`{id, label, re}`) |
| `NEXT_STEP_RE` / `QUESTION_RE` | 次アクション提案・質問の検出パターン |
| `MODES` | A/B/C の3モード定義(`aizuchi`, `interruptLen`, `maxStrikes`等) |
| `THEMES` | 評価テーマ4種(`id, name, desc, tip`) |
| `TITLES` / `titleFor()` | スコア→称号のマッピング |
| `SCENES` | シーン別台本(opener/beats/followups/closer、qaDrivenシーンはnuggets) |
| `JARGON_REPLIES` / `DISCOUNT_SHAKE` / `VALUE_ACK` / `INTERRUPT_C` / `SIMPLIFY_B` / `WALKOUT_C` | モード別の定型セリフ |
| `DISCOUNT_PUSH_INJECT` | テーマ2で価格シーン以外に1回だけ注入する値引き圧セリフ(モード別) |
| `CAT_KEYWORDS` / `CAT_NAMES` | テーマ4採点用の質問カテゴリ別キーワード・表示名(顧客の語彙に合わせて調整) |
| `FEEDBACK` | 評価テーマ別の改善点・言い換え例テンプレ(`t1.bad/good`, `t2.offered/lowValue/sufficient`, `t3.longOrInterrupted/noConclusion/good`, `t4.missed/good`) |

engine.js/speech.js/app.js は上記グローバルにのみ依存し、**商材固有の
文言や役職名を直接ハードコードしない**。新しいシナリオ追加時に
共有ファイルへ手を入れる必要が生じたら、それは大抵「本来data.js側に
あるべき文言が漏れている」サインなので、`FEEDBACK`等のテンプレへ移す。

## 運用思想(UXに反映する)

- 「明日の商談前に5〜20分だけ」の気軽な練習。セッション上限20分、残り時間タイマー表示(残り1分で警告)。
- 商談はフルシナリオでなく**シーン単位**: オープニング/ヒアリング/製品説明/価格提示/クロージング。
- フィードバックは**1回のロープレにつき評価テーマ1つだけ**。選択外の観点(声のトーン等)には一切言及しない。
- ゲーム性: 100点スコア、称号(例「◯◯攻略度72点：交渉見習い」)、連続実施記録。記録は`localStorage`の`salesRoleplayStats`キーに保存され、**全シナリオで共有**される(どのシナリオを練習しても連続日数・通算回数にカウントされる)。

## 顧客役の人格ルール(共通の型)

顧客役は「知らない専門用語がある」「関心事は決まっている」という2軸で
設定する。専門用語を使ったら**必ず**「それは何ですか？」と聞き返す
(同じ用語は1回だけ)。関心事に無いスペック説明ではなく、それが
顧客にとって何が嬉しいかへの「翻訳」を求める。

3モード切替式:
- **モードA(やさしい)**: 相槌を打つ。素直に質問。遮らない。
- **モードB(普通)**: 淡々と確認。わかりにくい説明(130字超で言い換えマーカーなし)に**1回だけ**「もう少し簡単に言うと？」。
- **モードC(忙しくて怖い)**: 冒頭で「5分しかない」と明言。110字超の前置きを遮る。値引きを強要。歯切れの悪い発言でストライク累積、3回で「よくわからないので結構です」と**商談打ち切り**(walkout→結果画面で減点)。短く結論から答えるとストライク回復。

## プレイヤー制約: 業界No.2・値引き不可

プレイヤーが値引きを**申し出たら**(拒否表現を伴わない値引き語)、顧客役は
「他社はもっと下げてくれる」「それなら他社にする」と揺さぶる。
値引きを断って価値カテゴリで切り返したら「値段だけじゃないってことね」と
認めて前に進む。

GC系3シナリオ(gc-center/gc-qa/gc-lab)は、基本4シーン(オープニング/現状
ヒアリング/課題深掘り/クロージング)に加えて**難易度ラベル付きの提案ケース
4シーン**(【初級】GC-2010更新提案/【中級】MMI提案/【上級】Agilent対抗提案/
【最上級】価格差・値引き交渉=priceScene)を`SCENES`に持つ8シーン構成。
難易度軸は共有ロジックに手を入れず、シーン定義だけで表現している。
「課題深掘り」はヒアリングと同じ`qaDriven`方式の第2シーンで、
「特に困っていない」→質問を重ねると小さな困りごとが開示される
**南口モデル(小さな困りごと発掘型)**を実装している。顧客役が専門家の
シナリオでも、JARGONの聞き返しは「部下や上層部に説明できる言葉に
言い換えて」という理由付けで成立させる。

## 対話エンジンの応答優先順位(RoleAI.respond、engine.js側の固定ロジック)

1. モードC: 長い前置き → 遮る(ストライク++)
2. 新出の専門用語 → 聞き返す
3. 値引きの申し出 → 揺さぶり
4. 値引き拒否+価値提示 → 承認プレフィックス(ストライク回復)
5. モードB: わかりにくい説明 → 1回だけ聞き返す
6. テーマ「値引き切り返し」選択時: 価格シーン以外でも1回だけ値引き圧を注入(`DISCOUNT_PUSH_INJECT`)
7. ヒアリングシーンは特殊(qaDriven): **質問されたときだけ**課題情報(nugget)を1つずつ開示。質問しないと「何をお聞きになりたいの？」
8. 通常シーン: beat(5〜6個)を順に消化 → followup → クローザーでセッション終了

## 評価テーマと採点(scoreSession、アルゴリズムはengine.js側の固定ロジック)

テーマは開始前に1つ選択。採点は選択テーマのみ:

1. **専門用語を使わない説明**: 用語使用ごとに-12(同一発言内に言い換えマーカーがあれば-6)、言い換え表現にボーナス
2. **値引き切り返し**: 基礎60点加点型。値引き申し出-30、拒否+10、価値カテゴリ初出+6(値引き圧直後なら+10)
3. **結論から簡潔に**: 基礎100点。遮られ-12、120字超-6、結論マーカー+4、平均100字超-10
4. **質問の意図を汲み取る**: `CAT_KEYWORDS`のカテゴリ(cost/diff/safety/ops/sched/need/next)と直後の回答のキーワード一致率で30+70×的中率

結果フォーマット(必須。文言は`FEEDBACK`テンプレから取得):
1. テーマ達成度 ◎(85+)/○(70+)/△(50+)/×
2. 良かった発言(実発言を1つ引用)
3. 改善点(**1つだけ**、具体的な言い換え例つき)
4. スコア100点満点+称号(90+達人/80+敏腕交渉人/70+一人前/55+見習い/40+駆け出し/修行中)

## 画面フロー

トップ(シーン選択) → 相手モード選択 → 評価テーマ選択 →
準備画面(選択サマリ+テーマのコツ+時間5/10/15/20分) →
ロープレ画面(タイマー/チャットログ/マイクボタン/テキスト切替/読み上げON-OFF/終了) →
結果画面(もう一度/次のテーマへ/トップ)

## 技術要件チェックリスト

- [ ] iPhone Safari / Windows Chrome・Edge で動作(webkitSpeechRecognition対応)
- [ ] STT非対応ブラウザでは自動的にテキスト入力モード、切替ボタンは常設
- [ ] TTSは `voiceschanged` で日本語ボイスを選択(`VOICE_PREF.genderRegex`で性別傾向を指定)、Safariのonend不発対策に保険タイマー
- [ ] マイクはタップして話す方式(自声拾い防止のためTTS中は認識しない)。音声で話した後は相手の返答終了時に自動でマイクを再開する
- [ ] **SpeechRecognitionインスタンスは使い回さず、startのたびに新規生成する**(iOS Safariは同一インスタンスの2回目以降のstartが無反応になる)。start()の例外は新インスタンスで1回だけ自動リトライ
- [ ] `100dvh` + `env(safe-area-inset-bottom)` でモバイルレイアウト
- [ ] タップターゲット44px以上、textareaのEnter送信はisComposing(日本語IME)を除外
- [ ] localStorageアクセスはtry/catchで包む(プライベートブラウズ対策)

## 検証方法

`python3 -m http.server` でリポジトリ直下を配信し、`/<シナリオ名>/` を
ブラウザで開いてテキスト入力モードで各シーン×各モードを1往復以上通す。

エンジン単体は node で、シナリオのdata.jsと共有engine.jsを連結して
確認できる(ブラウザAPI非依存のため):
`node -e "$(cat <シナリオ名>/js/data.js js/engine.js) …"` で
`RoleAI`/`scoreSession` の応答を検証する。**新シナリオ追加時は全シナリオで
このテストを回し、共有engine.jsに副作用が出ていないか確認する**こと。

Playwright(`/opt/pw-browsers/chromium`)でのE2Eスモークテストも、
STT非対応環境を`addInitScript`で模擬してフォールバック挙動を含めて
確認できる。複数シナリオがある場合は各`/<シナリオ名>/`パスに対して
同じテストを回す。
