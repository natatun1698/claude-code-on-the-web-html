# 営業ロールプレイングアプリ(部長攻略トレーニング)

医療機器営業向けの音声ロープレ練習Webアプリを新規構築、または既存実装
(`index.html` / `style.css` / `js/*.js`)を拡張するためのスキル。

## アーキテクチャ(必ず守ること)

**完全クライアントサイドの静的Webアプリ**として実装する。
サーバー・APIキー・ログインは一切使わない。これにより
「URLをクリックするだけで誰でも使える」要件を満たす。

- 部長AI = ルールベース対話エンジン(シーン別スクリプト + 発言のキーワード解析)
- 自動採点 = 同じ解析結果を使ったヒューリスティック(専門知識に依存しない単純基準)
- 音声 = ブラウザ標準の `SpeechRecognition`(webkit接頭辞対応) + `speechSynthesis`
- 非対応環境・認識失敗時はテキスト入力へフォールバック(機能停止させない)
- 記録(連続日数・通算回数・自己ベスト)は `localStorage`

### ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 全画面(section.screen)を1ページに持つSPA |
| `style.css` | スマホ縦画面ファースト、640px中央寄せ、700px以上で2カラムカード |
| `js/data.js` | 商材・専門用語・価値カテゴリ・モード・テーマ・シーン・セリフの全定義。**商材変更はこのファイルだけ触る** |
| `js/engine.js` | `analyzeUtterance()` / `BuchoAI`クラス / `scoreSession()` |
| `js/speech.js` | `SpeechIO`(音声認識・合成ラッパー、フォールバック判定) |
| `js/app.js` | 画面遷移・タイマー・チャットUI・localStorage |

## 運用思想(UXに反映する)

- 「明日の商談前に5〜20分だけ」の気軽な練習。セッション上限20分、残り時間タイマー表示(残り1分で警告)。
- 商談はフルシナリオでなく**シーン単位**: オープニング/ヒアリング/製品説明/価格提示/クロージング。
- フィードバックは**1回のロープレにつき評価テーマ1つだけ**。選択外の観点(声のトーン等)には一切言及しない。
- ゲーム性: 100点スコア、称号(例「部長攻略度72点：交渉見習い」)、連続実施記録。

## 顧客役: 診療科部長(高橋先生)の人格ルール

臨床には精通しているが医療従事者向けの装置スペックは専門外、という設定。
放射線科・装置・工事領域の専門用語(DICOM、FPD、管電圧、mAs、遮蔽工事、耐荷重等)は
知らず、営業が使ったら**必ず**「それは何ですか？」と聞き返す(同じ用語は1回だけ)。
逆に「被ばく」「処置時間」など臨床でなじみのある語は聞き返さない
(=専門用語リストと価値カテゴリのキーワードを重複させない)。
関心事は患者目線(被ばく・処置時間・安全性)と経営目線(稼働率・収益・差別化)の
メリットのみ。スペック数値でなく「患者さん・病院にとって何が嬉しいか」への
翻訳を求める。**年度内の機種選定、半年以内の設置・稼働**を計画している。

3モード切替式:
- **モードA(やさしい)**: 相槌を打つ。素直に質問。遮らない。
- **モードB(普通)**: 淡々と確認。わかりにくい説明(130字超で言い換えマーカーなし)に**1回だけ**「もう少し簡単に言うと？」。
- **モードC(忙しくて怖い)**: 冒頭で「5分しかない」と明言。110字超の前置きを遮る。値引きを強要。歯切れの悪い発言でストライク累積、3回で「よくわからないので結構です」と**商談打ち切り**(walkout→結果画面で減点)。短く結論から答えるとストライク回復。

## プレイヤー制約: 業界No.2・値引き不可

プレイヤーが値引きを**申し出たら**(拒否表現を伴わない値引き語)、部長は
「他社はもっと下げてくれる」「それなら他社にする」と揺さぶる。
値引きを断って価値(被ばく低減/処置時間短縮/安全性/実績/画質/AI/保守/稼働率/
収益/差別化)で切り返したら「値段だけじゃないってことね」と認めて前に進む。

## 商材設定(data.jsのPRODUCT。実情報に差し替え可)

- 血管撮影装置「Trinias OPERA B8」、本体のみ(オプションなし)約1億円
- 用途: 心臓カテーテル治療などに使う血管撮影装置(アンギオ装置)
- 強み: 少ないX線で血管がくっきり見える画像技術(被ばく低減) / 処置時間の短縮 /
  治療を止めない安全性・保守対応 / 全国の導入実績 / 高画質 /
  AIによる術者支援機能 / 故障時の駆けつけ・復旧の速さ

## 対話エンジンの応答優先順位(BuchoAI.respond)

1. モードC: 長い前置き → 遮る(ストライク++)
2. 新出の専門用語 → 聞き返す
3. 値引きの申し出 → 揺さぶり
4. 値引き拒否+価値提示 → 承認プレフィックス(ストライク回復)
5. モードB: わかりにくい説明 → 1回だけ聞き返す
6. テーマ「値引き切り返し」選択時: 価格シーン以外でも1回だけ値引き圧を注入
7. ヒアリングシーンは特殊(qaDriven): **質問されたときだけ**課題情報(nugget)を1つずつ開示。質問しないと「何をお聞きになりたいの？」
8. 通常シーン: beat(5〜6個)を順に消化 → followup → クローザーでセッション終了

## 評価テーマと採点(scoreSession)

テーマは開始前に1つ選択。採点は選択テーマのみ:

1. **専門用語を使わない説明**: 用語使用ごとに-12(同一発言内に言い換えマーカーがあれば-6)、言い換え表現にボーナス
2. **値引き切り返し**: 基礎60点加点型。値引き申し出-30、拒否+10、価値カテゴリ初出+6(値引き圧直後なら+10)
3. **結論から簡潔に**: 基礎100点。遮られ-12、120字超-6、結論マーカー+4、平均100字超-10
4. **質問の意図を汲み取る**: 部長の質問カテゴリ(cost/diff/safety/ops/sched/need/next)と直後の回答のキーワード一致率で30+70×的中率

結果フォーマット(必須):
1. テーマ達成度 ◎(85+)/○(70+)/△(50+)/×
2. 良かった発言(実発言を1つ引用)
3. 改善点(**1つだけ**、具体的な言い換え例つき)
4. スコア100点満点+称号(90+達人/80+敏腕交渉人/70+一人前/55+見習い/40+駆け出し/修行中)

## 画面フロー

トップ(シーン選択) → 部長モード選択 → 評価テーマ選択 →
準備画面(選択サマリ+テーマのコツ+時間5/10/15/20分) →
ロープレ画面(タイマー/チャットログ/マイクボタン/テキスト切替/読み上げON-OFF/終了) →
結果画面(もう一度/次のテーマへ/トップ)

## 技術要件チェックリスト

- [ ] iPhone Safari / Windows Chrome・Edge で動作(webkitSpeechRecognition対応)
- [ ] STT非対応ブラウザでは自動的にテキスト入力モード、切替ボタンは常設
- [ ] TTSは `voiceschanged` で日本語ボイスを選択(部長=男性設定のため男性系を優先)、Safariのonend不発対策に保険タイマー
- [ ] マイクはタップして話す方式(自声拾い防止のためTTS中は認識しない)
- [ ] `100dvh` + `env(safe-area-inset-bottom)` でモバイルレイアウト
- [ ] タップターゲット44px以上、textareaのEnter送信はisComposing(日本語IME)を除外
- [ ] localStorageアクセスはtry/catchで包む(プライベートブラウズ対策)

## 検証方法

`python3 -m http.server` で配信し、ブラウザでテキスト入力モードを使って
各シーン×各モードを1往復以上通す。エンジン単体は node で
`node -e "$(cat js/data.js js/engine.js) …"` のように連結して
`BuchoAI`/`scoreSession` の応答を確認できる(ブラウザAPI非依存のため)。
Playwright(`/opt/pw-browsers/chromium`)でのE2Eスモークテストも、
STT非対応環境を`addInitScript`で模擬してフォールバック挙動を含めて確認できる。
