# ラガマフィンとさんすう(sansu-mihana)

小学5年生の弥花さんのための算数復習アプリ。ラガマフィン(猫)のキャラクターが
ずっと隣で伴走し、正解すると名前を呼んでほめてくれる。
「勉強させる」より「猫と遊んでいたら算数が得意になっていた」という体験を作るのが目的。

公開URL: `https://natatun1698.github.io/claude-code-on-the-web-html/sansu-mihana/`

## ファイル構成

| ファイル | 役割 |
|---|---|
| `sansu-mihana/index.html` | 4画面(タイトル/モード選択/出題/結果)＋猫のインラインSVG(`<template id="cat-svg">`) |
| `sansu-mihana/questions.js` | 学習データ `QUESTIONS`(全29問)と分野定義 `FIELDS` |
| `sansu-mihana/app.js` | 出題ロジック・採点・猫のリアクション・進捗管理 |
| `sansu-mihana/style.css` | 配色・レイアウト・猫のCSSアニメーション |
| `sansu-mihana/README.md` | 仕様と取り扱い注意 |

ビルド不要。`index.html` をブラウザで開けば動く。外部通信・ログイン・APIキーなし。

## 絶対に守ること

この3つは子どもへの配慮とコンプライアンスに直結するので、ほかの改善より優先する。

1. **得点・偏差値・順位・志望校判定を絶対に画面に出さない。** 成績表から使ってよいのは
   正誤(○×―)・全体正答率・思考スキルタグだけ。数字でプレッシャーをかけない。
2. **まちがえたときに否定的・がっかりした演出をしない。** ×印や減点音は使わず、
   💡と前向きなセリフ＋やさしい解説にする。まちがいは「強くなれるチャンス」として扱う。
3. **模試の問題がもとなので、公開範囲を広げる変更をしない。** `<meta name="robots" content="noindex...">`
   を外さない。SNS共有ボタンやOGP、検索エンジン向けの導線を足さない。

## 学習データの追加・修正

`questions.js` の `QUESTIONS` に1問1オブジェクトで追加する。

```js
{ id:"1-1", big:1, no:"(1)", field:"calc", title:"だい1もん 計算",
  setup:"（任意）問題の前提。図の寸法などは文章で言い切る",
  q:"2026 － 2025 ÷ 45", ans:"1981", type:"int", unit:"cm",
  mark:"x", rate:71.5, skill:"A1",
  hint:"解き方の入口だけを示す。答えは書かない",
  exp:"式を1行ずつ。正解は <b>…</b> で強調。最後に一般化できるコツを1つ" }
```

- `field` … `calc`(計算) / `number`(数の性しつ) / `figure`(図形) / `word`(文章題)。
  分野別がんばり度バーとバッジに直結する。
- `mark` … 弥花さんの過去の結果。`"x"`=まちがえた(重み5) / `"-"`=無回答(重み4) / `"o"`=正解(重み1)。
  **出題頻度そのものなので、成績データを正しく写すこと。** ここを適当に埋めると
  「苦手を優先する」というアプリの存在意義が崩れる。
- `type` … `int` / `dec` / `frac`。`frac` のときだけ入力欄に分数の書き方を案内する。
- `unit` … 表示用。`cm2`・`cm3` は `unitLabel()` が cm²・cm³ に変換する。
  採点では単位を無視するので、入力必須にはしない。
- `rate` … 全体正答率。今は参考値として保持するだけで画面には出していない。

**図に数字が埋め込まれていて解説を確定できない問題は、推測で埋めずに出題から外す。**
まちがった解説を子どもに見せるより、その1問がない方がよい。外したときは
`sansu-mihana/README.md` に理由を1行残す(大問2(4)がその実例)。

### ヒントと解説の書き方

解答解説をそのまま写さない。ラガマフィン先生が小5に話しかける言葉に翻訳する。
思考スキルタグも子どもの言葉に置き換える(「特徴的な部分に注目する」→「目立つ数字に注目してみよう」、
「順序立てて筋道をとらえる」→「順番に整理して考えてみよう」)。
語尾に「にゃ」を混ぜるが、解説の本文まで崩すと読みにくいので、崩すのは最後の一言くらいにとどめる。

## 出題ロジック(app.js)

- `weightOf()` が `mark` から重みを返し、`weightedPick()` が重み付き抽選する。
  直前と同じ問題は候補から除外する。
- モードは3つ。`buildSession(mode)` が返す配列がそのままセッション。
  - `weak` … 重み付き10問(デフォルト)
  - `order` … 大問順に全問
  - `again` … `state.wrongIds`(アプリ内でまちがえた問題)だけ。空ならその旨を伝えて戻す
- セッション中にまちがえた問題は `S.missed` に貯め、最後に**リベンジタイム**として
  もう一度だけ出す(`next()` 内)。リベンジ中の誤答は再収集しない(無限ループを避けるため)。
- 進捗は `localStorage`(キー `sansu-mihana-v1`)にだけ保存する。サーバーには送らない。
  スキーマを変えるときはキーを `-v2` にして、古いデータで壊れないようにする。

## 採点(judge)

`normalize()`(全角→半角・空白除去)→ `stripUnit()`(cm/本/枚/円/度/通り等を末尾から除去)→
`parseFraction()`(`1/4`・帯分数・小数)→ 数値比較、の順。等価分数(`2/8`)も正解になる。
新しい単位を扱う問題を足したら `UNIT_RE` に追加すること。

## 猫(ラガマフィン)

- **画像ファイルを使わない。** `index.html` の `<template id="cat-svg">` にインラインSVGがあり、
  `.ragamuffin` クラスの要素すべてに複製して差し込んでいる。パーツを足すときはSVGに
  `<g class="…">` を追加し、`style.css` の `[data-level]` セレクタで表示を切り替える。
- セリフは `app.js` の `PRAISE` / `ENCOURAGE` / `COMBO`。`pick()` でランダム表示。
  **同じセリフが続くと飽きるので、追加するときは1〜2本ではなく数本まとめて足す。**
  ほめ言葉には名前(`NAME`)を織り交ぜる。名前を変えるだけで別の子向けにできるよう、
  文中に直書きせずテンプレートリテラルで `${NAME}` を使う。
- 成長は `level()`(ポイント閾値)→ `data-level` 属性 → CSSで見た目が変わる方式。
  新しい見た目を足すときは `LEVEL_NAME` と閾値も一緒に更新する。

## 変更したら必ず確認する

1. 全問の正解判定 — 正解文字列そのもの、前後に空白、単位つき、全角数字、
   分数問題は等価分数でも○になるか。誤答と空欄が×になるか。
   Node で `questions.js` と `app.js` の採点部分を読み込んで一括テストするのが速い。
2. 重み付き抽選 — 数百セッション分抽出して `mark:"x"` の比率が高いこと、
   同じ問題が連続しないこと。
3. 表示 — スマホ幅(430px)とPC幅で崩れないこと、JSエラーが出ないこと。
   常駐する猫が問題文やボタンに重ならないこと(`body` の `padding-bottom` で逃がしている)。
4. セリフが毎回同じにならないこと。
