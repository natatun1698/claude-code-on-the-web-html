# X フィード・デイリーダイジェスト

X のフォロー中タイムラインを Playwright で収集し、1日分の投稿を読みやすいダイジェストにまとめるskill。
ユーザー本人 (@UmetsuTakahiro) のアカウントのログインセッションを使う。個人の閲覧補助が目的なので、実行は1日1回程度にとどめること。

## 実行手順

以下のステップを順番に実行する。パスはすべてこの SKILL.md があるディレクトリ（以下 `$SKILL_DIR`）からの相対。

### ステップ 1: 前提条件の確認

1. `node --version` で Node.js (v18以上) があることを確認する。
2. `node -e "import('playwright')"` を実行し、失敗したら次を実行してインストールする:
   ```bash
   npm install playwright
   npx playwright install chromium
   ```
   (環境変数 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` が設定された環境では `npx playwright install` は不要。`executablePath` が解決できない場合のみ相談する。)

### ステップ 2: タイムラインの収集

```bash
node "$SKILL_DIR/scripts/fetch_timeline.mjs" fetch
```

- 成功すると `./x-digest/raw-YYYY-MM-DD.json` に投稿データが保存され、件数が表示される。
- **終了コード 2（標準エラーに `NOT_LOGGED_IN`）の場合**: 初回ログインが必要。ユーザーに「ブラウザが開くのでXにログインしてください」と伝えたうえで次を実行し、完了後にステップ2をやり直す:
  ```bash
  node "$SKILL_DIR/scripts/fetch_timeline.mjs" login
  ```
  （ログインセッションは `~/.x-digest-profile` に保存され、次回以降は不要になる。）
- 対象期間を変えたいと言われたら `DIGEST_HOURS=48` のように環境変数で指定する（既定は24時間）。
- 収集件数が0件の場合はエラーとして扱い、`HEADFUL=1` を付けて再実行して画面の状態（ログイン切れ・確認ダイアログ等）を確認する。

### ステップ 3: ダイジェストの生成

保存された JSON（`tweets` 配列。各要素に `handle` / `name` / `datetime` / `text` / `url` / `isRepost` / `quoted` / `hasMedia` を含む）を読み込み、以下のルールで **日本語の** ダイジェストを書く。

**前処理:**
- ユーザー本人の投稿（`handle` が `@UmetsuTakahiro`）は除外する。
- ほぼ同一内容の重複（同じ投稿のリポストが複数人から流れてきたもの等）は1件にまとめ、「◯人がリポスト」と注記する。
- 投稿が多い場合（150件超）も全件に目を通し、重要度で取捨選択する。省略した旨は統計に書く。

**出力フォーマット** — `./x-digest/digest-YYYY-MM-DD.md` に保存する:

```markdown
# Xデイリーダイジェスト YYYY-MM-DD

## 📌 今日のハイライト
（最重要の3〜5件。1件2〜3行で要約し、投稿者名と元投稿へのリンクを付ける）

## 🗂 トピック別まとめ
（内容の近い投稿をトピックごとにグルーピングし、トピック名を見出しにして要約。
 各トピック2〜6行。個々の言及には (投稿者名)[URL] 形式でリンクを付ける）

## 🔗 注目リンク
（投稿内で共有されていた記事・リポジトリ・動画などの外部リンクを、一言説明付きで箇条書き）

## 📊 統計
- 対象期間・総投稿数・除外件数
- 投稿数の多かったアカウント上位5件
```

**要約の方針:**
- 事実と投稿者の意見を区別して書く（「〜と報告」「〜という意見」）。
- 話題が割れているときは両論を併記する。
- 単なる挨拶・雑談・宣伝のみの投稿はハイライトやトピックに含めない。
- ユーザーは日本語話者。英語投稿も日本語で要約する。固有名詞は原文のまま。

### ステップ 4: 提示

生成した digest ファイルの内容をそのまま返信で見せる（ファイルパスだけ伝えて終わらないこと）。

## トラブルシューティング

- **「フォロー中」タブが見つからない警告**: X のUI変更の可能性。`HEADFUL=1` で実行して実際の画面を確認し、`scripts/fetch_timeline.mjs` のタブ名の正規表現を修正する。
- **収集が途中で止まる / 件数が少なすぎる**: スクロール上限（`MAX_SCROLLS`）に達した可能性。フォロー数が多い場合はスクリプト冒頭の `MAX_SCROLLS` を増やす。
- **セッション切れが頻発する**: `~/.x-digest-profile` を削除して `login` からやり直す。

## 注意事項

- このskillはユーザー本人のアカウントで、本人が読むためのタイムライン収集のみに使う。他者アカウントの収集・大量スクレイピング・再配布には使わない。
- 収集データ（`x-digest/`）とブラウザプロファイル（`~/.x-digest-profile`）にはプライベートな情報が含まれるため、リポジトリにコミットしない。
