# スキャン名簿PDFの年次差分 → Excel 化スキル

## 概要

雑誌の設置施設名簿(画像スキャン、見開き、1ページ4段組、各段は
「病院名列+システム列」のペア構造)の新旧2版を比較し、新版で追加された
システム(=期間中に導入されたと推定)を抽出する。

処理は `scripts/` の実証済みパイプラインを使う。**ゼロから書き直さないこと。**
2024/2025年版の実運用で判明した落とし穴が全てスクリプトに織り込まれている。

**最重要原則: OCRだけの差分は絶対に納品しないこと。** OCR差分の約8割は
旧版側の読み落とし・帰属ズレによる偽陽性。必ず目視検証(手順6)を通す。

## 前提セットアップ

```bash
sudo apt-get update && sudo apt-get install -y poppler-utils tesseract-ocr tesseract-ocr-jpn
pip install pillow numpy rapidfuzz openpyxl
```

PaddleOCR等のDLモデルはプロキシ遮断で使えない環境がある。tesseractで動く設計。

## パイプライン(順番に実行)

作業ディレクトリ(スクラッチパッド)にこのスキルの `scripts/*.py` をコピーして進める。

### 1. PDF調査(必ず最初に)

- `pdfinfo` でページ数・サイズ確認(システム通知のページ数は誤ることがある)。
  `pdftotext -layout` を試し、テキスト層があれば簡易パスも検討(通常は空)。
- `pdftoppm -r 600 -gray -png`(A4見開きスキャン)/ `-r 500`(A3撮影)で全ページ描画。
- **各PDFの数ページを Read で目視**して以下を確認する:
  - 誌面ページ番号(フッター `(121) 新医療 …`)と**ページ順序**。
    スキャンPDFはページ順が入れ替わっていることがある(実例: pg-03とpg-04が逆)。
    読み順は誌面番号の降順。
  - **収録範囲**。実例: 旧版=Part1(北海道〜神奈川)+Part2(新潟〜)の合本、
    新版=Part1のみ → 比較範囲は共通部分(北海道〜神奈川)のみ。
    「※新潟県以降は7月号に掲載予定」等の注記が手がかり。
  - 基準日(「YYYY年3月1日現在」)→ 導入年推定の根拠。

### 2. セグメンテーション+OCR

- **フラットスキャン(A4見開き)**: `python3 extract3.py <spread.png> <outdir> <base>`
  (ノド分割→傾き補正→ページ毎に4ペア切り出し)
- **書籍を撮影したもの(湾曲・影あり)**: `python3 extract4.py <spread.png> <outdir> <base>`
  (**ノド分割せず見開き全体を8ペアに直接分割**。撮影本はノド分割が必ず失敗し、
  端のペアが泣き別れて病院名とシステムの対応が壊れる — 実際に起きた)

内部処理(いずれも実際に必要だった対策):
- 段組境界は**バンド分割検出→行ごとに補間した曲線でマスク切り出し**
  (湾曲・傾きがあるためページ全体の直線カットは失敗する)
- ペア境界の同定は「red トラック=病院名列|システム列境界」を
  **+55〜115pxに相棒トラック(メーカー記号|機種名の隙間)を持つ**ことで
  フィルタする(この規則で全見開き×8本が完全一致した)。カット位置は red−340px
- OCRは2パス: システム列=jpn+eng 2倍拡大 / 病院名列=**jpn単独 3倍拡大**
  (jpn+engだと病院名がラテン文字のゴミになる)
- 県ヘッダー網掛けバーは画像として検出(`header_bars`)。tesseractではほぼ読めない

### 3. 構造化 (`parse.py`)

- ORDER_2024 / ORDER_2025 を実ページ構成に合わせて書き換える(手順1の結果)
- システム行の開始判定は機種ファミリ辞書とのファジー一致(`canon.py`)。
  メーカー記号(フ・キ・シ・G・島)はOCRで崩れるため記号だけに頼らない。
  オプション行(DSA,FPD,シネ,3D,Net等のみの行)をファミリ照合から除外する
  ガードが入っている(FPD→ACT FP等の誤マッチが多発した)
- 病院名の折返し結合: 「システム開始行と縦位置が揃う名前行=新病院、
  揃わない=折返し」

### 4. 県割当 (`assign.py`)

検出バーは誤検出(撮影影・ページ端)と読み落としが必ずある。**バー候補の
クロップモンタージュを1枚作って Read で目視し、真偽と県名を確定してから**
`verified_bars_YYYY.json`(page/side/strip/y/pref)を書き、割当を実行する。
順序は固定(北海道→…→神奈川)なのでシーケンスで自己検証できる。
県別病院数を両年で見比べ、大きなズレ(>±30%)は異常のサイン。

### 5. 差分 (`diff.py`)

- 県内で病院列を**順序保存DP整列**(Needleman-Wunsch、ファジー名称一致)
  — 貪欲マッチはOCR崩れ名で誤対応を量産する
- 正規化機種名の集合差で「新版のみのシステム」候補を出す。
  同ファミリ変種(FD10↔FD10/10、B12↔B20等)はOCR揺れとして自動棄却。
  出力 `candidates.json`(数百件になるが正常。大半は偽陽性)

### 6. 目視検証(必須・省略禁止)

`python3 make_montages.py 6` で候補ごとに新旧クロップを並べた
モンタージュ(6件/枚)を生成し、**全バッチを Read で読んで1件ずつ判定**する。
判定基準:
- 旧版の同病院欄(±隣接病院を含む)にそのシステムが本当に無いか
  → あれば棄却(旧版OCR読み落とし/帰属ズレが最頻の偽陽性)
- ラベルの機種名は新版クロップの実際の印字と一致するか(誤読補正して採用)
- **ラベルと違う真の差分がクロップ内に見えたらそれを採用**
  (例: ラベルはAzurion追加だが実際はINFX→Alphenix Biplane更新だった)
- クロップが途切れて判定不能なもの・sim<50の弱マッチはフォローアップリストに
  積み、大きめクロップで再確認
- 病院名変更(改称・移転)は変更システムのみ採用
判定結果を `verified.json`([{pref,hospital,maker,model,year}])に集約。
偽陽性率は8割前後が正常なので、採用件数が候補の2-3割を超えたら疑うこと。

### 7. Excel生成 (`make_excel.py`)

`python3 make_excel.py verified.json 出力.xlsx`
列: 都道府県 / 病院名 / メーカー名 / システム名 / 予想される導入年。
導入年は両版の基準日の間(例: 2024年3月〜2025年2月)。注記シートに
方法・対象範囲・限界を必ず書く。SendUserFile で納品。

## メーカー記号の凡例(この名簿固有)

フ=フィリップス、キ=キヤノン(旧東芝)、シ=シーメンス、G=GE、島=島津製作所。
機種ファミリ辞書(canon.py FAMILIES)に無い新機種が出たら辞書に追加する。

## 重要な教訓

- 段組カット失敗は「病院名と隣ペアのシステムの誤結合」として現れる。
  パース結果が変なら、まずセグメンテーション画像を目視する
- 実データでの規模感: 14道県・約700病院・約1500システム/年、
  OCR差分候補 約260病院分 → 目視検証後の真の更新は40〜60台程度
- モンタージュがAPIに拒否されることが稀にある → そのバッチだけ
  分割・スケール変更して再生成する
- 検証Readは2枚/メッセージで並列化すると速い
