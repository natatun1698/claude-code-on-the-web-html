# AICX AIエージェント導入ワークシート記入スキル

AICX認定資格の公式ワークシート(Excel)を、指定された業務ケースの内容で記入するスキル。
テンプレートは `assets/blank_template.xlsx`(ユーザーが別のテンプレートをアップロードした場合はそちらを優先)。

## 手順

1. **ケースを確認する**: 引数またはユーザーの依頼から対象業務(例:「請求書発行」)を特定する。不明なら聞き返す。
2. **ケース定義JSONを作る**: `examples/invoice_agent.json`(請求書発行ケースの完成例)をひな形にコピーし、下記の記入ガイドに従って全項目をケースに合わせて書き換える。作業ファイルはスクラッチパッドに置く。
3. **スクリプトで記入する**:
   ```bash
   pip install openpyxl  # 未インストールの場合のみ
   python3 scripts/fill_worksheet.py \
     --template assets/blank_template.xlsx \
     --case <ケース定義.json> \
     --out <出力ファイル名>.xlsx
   ```
   出力ファイル名は「AIエージェント導入ワークシート_<ケース名>_記入済み.xlsx」とする。
4. **検証する**: openpyxlで出力を開き直し、(a) 全シートに値が入っているか、(b) Ch06のE列8〜42行に未記入がないか、(c) Ch05の各行にAがちょうど1つ・Rが1つ以上あるかを確認する。
5. **納品する**: SendUserFileで出力xlsxをユーザーに送る。ケースの要点(対象業務・成功基準・最終判断)を1段落で添える。

## ワークブック構造とJSONスキーマ

シート名は変更しないこと。行・列の対応:

| JSONキー | シート | 記入場所 |
|---|---|---|
| `ch01.rows[]` | Ch01_任せたい仕事 | 7行目=No.1から1行ずつ。B部門/C業務名/D困りごと/E対象頻度/F工数(分)/H期待効果/J優先度/Kメモ。G(月間工数)とI(期待効果h)は数式で自動計算(スクリプトが7〜9行目に数式を補完する) |
| `ch02` | Ch02_SIPOC_As-Is | C4対象業務/E5作成日/F5作成者。`sipoc`はB9〜F9。`asis`のoverview/owner/tools/issuesは18〜21行目、各5要素(B受付/C確認/D判断/E出力/F備考) |
| `ch03_04.rows[]` | Ch03-04_データ・ワークフロー | 7行目=「1起点」〜14行目=「8記録・監査」の8行固定。B内容概要/C入出力(io)/Dツール(tool)/E担当(owner: AI・人・AI+人)/F品質基準(quality)/G備考(memo) |
| `ch05.rows[]` | Ch05_推進体制・責任 | 7〜13行目=タスク1〜7(タスク名は固定)。`marks`はC〜I列の7役割(業務担当/業務MGR/IT開発/IT運用/セキュリティ/経営層/ベンダー)へのR・A・C・I。Jメモ |
| `ch06` | Ch06_5D進行チェック | B4案件名/F4対象業務/B5作成者/D5作成日/F5最終判断/H5参照資料。`results`は行番号→E列(確認結果・参照先)。`memos`は行番号→H列 |

Ch06の行番号: Discovery=8〜12、判定=13 / Definition=14〜19、判定=20 / Design=21〜27、判定=28 / Development=29〜35、判定=36 / Deployment=37〜41、判定=42。各行のD列「確認すること」とF列「記入例」を読み、それに答える内容をE列に書く。

## 記入ガイド(内容の品質基準)

- **Ch01の対象頻度**: G列の数式が解釈できる形式のみ使う — `毎日`(月20回換算)、`週N回`、`月N回`、または数値。それ以外の表記は月間工数が計算されない。
- **数字の一貫性**: 件数・工数・成功基準などの数字はCh01/Ch02/Ch06で矛盾させない(例: Ch01で月150回なら、Ch06の困りごとも月150件)。
- **Ch06のE列**: 「結果・数値 + `\n参照：<資料名>`」の2行形式で書く(記入例のスタイルに合わせる)。判定行(13/20/28/36/42)は `Go：理由` / `Pivot：理由` / `No-Go：理由` の形式、H列に `責任者：○○` を書く。
- **判定のストーリー**: 5つのStepの判定は一貫した物語にする。PoC結果(29〜35行)は成功基準(18行)・評価条件(27行)と対応する実測値を書き、失敗パターン→原因仮説→改善バックログがつながるようにする。
- **安全設計**: 権限・禁止事項、HITL(人の確認)、自動実行の禁止範囲(例: 自動送付禁止)を必ず具体的に書く。AIに任せる工程と人が残す工程の境界を明確にする。
- **Ch05のRACI**: 各行にA(最終責任)はちょうど1つ、R(実行責任)は1つ以上。空欄は空文字列にする。
- **複数行テキスト**: JSON内の`\n`が改行になり、スクリプトが折り返し表示を設定する。1セル3行程度まで。
