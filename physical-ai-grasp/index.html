01

The answer成功させたければ、まず時刻を合わせる。
loss は何も教えてくれない

3条件の実測。観測と行動のペアが 350 ms ずれているだけで、成功率は 0.88 → 0.22 まで落ちる。 にもかかわらず、下の学習曲線では dirty 条件も普通に収束している。 「学習が回ること」と「ロボットが動くこと」は別物、という結論がこの1枚に出ています。

1フレームのずれは loss に現れず、実機で暴れる。 観測と行動の対応がずれたデータは「もっともらしく学習できてしまう」ため、 学習ログを見ている限り事故に気づけません。判定できるのは rollout の成功率だけです。
02

Dose response何 ms のずれから壊れるのか

ずれ幅だけを 0 / 100 / 200 ms と変えて学習した講師の実測（各100 rollouts）。 100 ms は約6pt 低下＝誤差の範囲、200 ms で約24pt 低下＝はっきり有意。 つまり数十 ms の遅れは許容できるが、100 ms を超えたあたりから方策が壊れ始めます。

観測と行動のずれ成功率（100 rollouts）判定
0 ms80%基準
100 ms74%約6pt低下 ＝ 誤差の範囲
200 ms56%約24pt低下 ＝ 有意
350 ms（別実験）22%ほぼ機能しない
03

The pipeline「集める」で終わらせない。検証までがデータづくり

講義全体の主張がこの1枚。データスケールとは収録時間を増やすことではなく、単位コスト当たりに 「同期され・多様で・正しくラベル付けされ・検証可能な軌道」をどれだけ作れるか。 今日の演習は、その5工程を1周する構成でした。

  • 収集はもうスケールし始めた。次の律速は処理 —— 集めやすい手段ほど後処理が重い（UMI＝SLAM、ego＝ラベル生成）。量は「時間」ではなく「多様性」で数える。
  • (o,a) ペアは同期処理が作る。良いデータ ＝ 量 × 多様性 × 実行品質 × ラベル品質。有効な軌道は資産、ラベルは修理可能な部品（filter / relabel / condition）。
  • 検証までがデータづくり。可視化・統計・実機リプレイまでやって、はじめて1周。
04

Step 1 ／ Inspectまず時刻の健全性を測る

トピックごとに median(stamp − recv)［ms］を出すだけで、壊れた bag が1発で浮かびます。 正常な bag は全トピックが −8〜−10 ms 程度の一定オフセット（デバイスが打った時刻の方がわずかに古い＝正常）。 ところが ep_006 の /joint_states だけ +348.2 ms。これがレイテンシ異常です。

05

Step 2 ／ Sync最近傍マッチで (o, a) ペアを作る

カメラ（agentview）のフレーム時刻を基準に、他トピックから slop 以内の最も近い時刻を拾う。 slop を超えたら None ＝ そのフレームは捨てる。関節は補間、ただし範囲外は捨てる。 ここで作られた対応が、そのまま学習データの (観測, 行動) ペアになります。

ここが一番の落とし穴：レイテンシ異常だった bag も、採用率は下がりません。 トピック間で「一定量ずれたまま」揃っていれば、最近傍マッチは何食わぬ顔で成立してしまう。 採用率チェックだけでは同期ずれを検出できないので、Step 1 の遅延テーブルと、次の目視確認が必要になります。
06

Step 3 ／ Format資産化する。そして「掴む瞬間」を目で確かめる

同期済みフレームを LeRobotDataset に変換して、あとから誰でも読める形にする。 finalize() の呼び忘れはメタデータが書かれず「壊れたデータセット」になる——公式 docs の Common Issues 筆頭です。

この目視チェックが、実務でいちばん効く同期テストです。数値では気づけないずれが、 「掴む前に閉じている／掴んだ後に閉じている」という形で必ず見えます。
07

Step 4a ／ Curate処置は3種類しかない：keep / filter / relabel

見つけた問題にどう対処するかを、エピソード単位で表に書く。 「成功しているけど下手」なテイクを keep するか filter するかに、一意の正解はありません。 根拠を書けることが評価軸——というのが演習の建て付けでした。

08

Step 4b ／ Relabelラベルの間違いは、捨てずに直す

埋め込み空間で leave-one-out の kNN 多数決を取り、付与ラベルと予測が食い違うエピソードを「容疑者」として自動抽出。 出てきた2本を目視すると、映像は can のピック&プレースなのに指示文は lift ——ラベルの付け間違いでした。

有効な軌道は資産、ラベルは修理可能な部品。 ロボットの動き自体が良いなら、ラベルを直せば学習データとして生き返ります。 filter（捨てる）より relabel（直す）を先に検討する理由がここにあります。
09

Step 5 ／ Compare「下手なデータは捨てるべき」は実測に裏切られる

3つのチェックポイントは、方策も学習規模も同じ。違うのはデータだけ。 ②（同期修正・worse 100本込みで300本）が 0.88、③（さらに worse を除いて200本）が 0.54。 捨てた分だけデータ量とカバレッジが痩せた——講義で言う filter の副作用そのものです。

条件やったこと本数成功率
cond1_dirty同期ずれ（+350 ms）を放置3000.22
cond2_sync時刻同期だけ修正（worse 込み）3000.88
cond3_curated同期修正＋worse を filter2000.54
効いた順番：①同期の修正 ＞＞ ②キュレーション。 しかも、きれいにキュレーションした③より、雑に見える②の方が強い。 この規模では「量とカバレッジ」の方が「1本ごとの上手さ」より効く、ということです。
10

Playbookつかませるための7手順

上から順に、効果の大きい順です。多くの場合、1〜3 を直すだけで成功率は跳ねます。

  1. 時刻の健全性を測るトピック別 median(stamp − recv)。数十 ms の一定オフセットは正常、数百 ms は異常。1本でも外れ値があれば、そこから先の全工程が汚染される。
  2. 最近傍マッチ＋slop で (o, a) ペアを作り直す基準はカメラ時刻。slop は「採用率」と「マッチ残差のヒストグラム」の両方を見て決める。採用率が高いことは、同期が正しい証拠にはならない。
  3. 「掴む瞬間」とグリッパ指令の立ち上がりを目視で突き合わせるいちばん安くて、いちばん確実な同期テスト。ここが一致していなければ、学習しても掴めない。
  4. loss で判断しない汚れたデータでも loss は普通に収束する。判定は rollout の成功率だけ。評価用に必ず数十本の rollout を回す。
  5. 捨てすぎない「下手だが成功」は資産。filter で 0.88 → 0.54 まで落ちた実測がある。除外の前に「これで量と多様性がどれだけ減るか」を数える。
  6. ラベルは直すkNN 多数決などで容疑者を自動抽出 → その数本だけ目視 → relabel。捨てるのは「直せない汚れ」だけ。
  7. 判断の根拠を残すdecision / method / reason を単位付きの数値で書いた判断表。再現できない品質改善は、次のデータで再現できない。
11

Next自分で線を1本引いてみる

講義の締めに出された発展課題。最小構成なら T4 で1条件 10〜12分なので、 「データ品質 → 成功率」を自分の手で確かめられます。

  • Step 6 のミニ実験を1条件やる。分担して 0 / 100 / 200 ms の3点カーブを埋める。
  • 自分のルールでフルデータをキュレーション → 再学習。閾値（長さ・jerk・レイテンシ）を適用して、講師の② 88% を超えられるか。
  • ①の bag をオフセット推定で「救って」再同期し、学習に加えると成功率は上がるか。
