# CVS納入リストPDF → Excel台帳 突合・転記

適用する3ルール（ユーザー指定）:

1. **ExcelとPDFでシステム名が同じ** → その行はそのまま
2. **システム名が異なる**（装置更新）→ メーカー・システム・納入年度（=リストの年）を書き換え
3. **ExcelにあるがPDFにない** → 備考に「(年)年リスト未掲載」と追記して未掲載と分かるようにする

作業は2段階に完全分離されている。**判断が必要なのはStep 1（PDF精読と転記）だけ**であり、
突合・書き込み・書式・レポートはすべて同梱スクリプトが機械的に行う。
スクリプトを書き直したり、自前のコードでExcelを直接編集したりしないこと。

## Step 1: PDFを精読して transcription.json を作る

対象PDFはスキャン画像でテキスト抽出できない。必ず高解像度レンダリング＋分割拡大で読む。

```bash
pdftoppm -r 300 -png リスト.pdf page        # → page-1.png (2550x3300程度)
```

pdftoppmが無い環境では:

```python
import pypdfium2 as pdfium
pdfium.PdfDocument("リスト.pdf")[0].render(scale=4.0).to_pil().save("page-1.png")
```

読み方（ここで手を抜くと全てが壊れる）:

- 誌面は縦4〜5列組み。PILで**列ごとにクロップ→2倍拡大→さらに上下半分に分割**して保存し、
  1枚ずつ画像として精読する。ページ全体1枚のまま読み取らないこと。
- 「◆◯◯県」の見出しで対象県の開始位置を特定する。終了は次の「◆」見出しまたは誌面末尾。
  県のセクションは列の途中で始まり、**次の列の先頭に前の病院の装置行が続く**ことがある。
  病院名の無い装置行は直前の病院名に属する。隣県の病院を混入させない。
- 曖昧な文字（型式の枝番、[B]/[S]、丸囲みマーク）はその部分だけ再クロップ・拡大して確認する。
  それでも読めない場合は読めた範囲だけ記録し、**推測で補完しない**。

### 誌面の表記規則（新医療誌系）

- 1行の構造: `病院名 メーカー略号・(マーク) システム名 [面数] 機能,機能,...`
- メーカー略号: **フ=フィリップス、キ=キヤノン、シ=シーメンス、島=島津、G=GE**
- 丸囲みマーク: **Ⓤ=更新、Ⓒ=既設、Ⓝ=新規**。過去の導入経緯の累積表記であり
  「その年の納入」を意味しない。判定には使わず、そのまま転記する（スクリプトが要確認事項の
  フラグに使う）。
- 面数: **[B]=バイプレーン、[S]=シングル**
- 「Trinias シリーズ」のように型式を省略した記載がある。原文どおり転記する
  （スクリプトがシリーズ一致として扱う）。

### transcription.json の形式

```json
{
  "prefecture": "沖縄県",
  "year": 2026,
  "aliases": {
    "琉球大学病院": "琉球大学医学部附属病院"
  },
  "hospitals": [
    {"name": "石垣島徳洲会病院",
     "devices": [
       {"maker": "フ", "system": "Azurion 3 M15", "plane": "S", "mark": "U"}
     ]}
  ]
}
```

- `prefecture` はExcelの「県」列の値と完全一致させる（「沖縄」ではなく「沖縄県」）。
- `hospitals` はPDFの掲載順に、装置はPDF原文のまま転記する。
- `plane` は "B"/"S"/""、`mark` は "U"/"C"/"N"/""。
- `aliases` はPDF病院名がExcelの病院名と部分一致しない場合のみ、
  Excel側の**正確な文字列**（法人名・全角スペース・末尾空白含む）を指定する。
  最初は空でよい（Step 2のエラー/レポートで不足が分かる）。

## Step 2: スクリプトで突合・書き込み

```bash
python3 <このスキルのディレクトリ>/scripts/merge_cvs_list.py \
    --excel 元台帳.xlsx --data transcription.json --out 更新済み.xlsx
```

スクリプトが行うこと:

- 病院名の自動マッチ（正規化した部分一致）。曖昧・不一致はエラー/レポートで顕在化するので、
  `aliases` を追記して再実行する。
- ルール1の「同じ」は正規化後の包含一致まで許容（例: PDF「Azurion 7 B20」= Excel「Azurion7 B20/15」、
  「Trinias シリーズ」= 「Trinias B12 MiX」）。メーカー一致も要求。
- ルール2の更新ペアは同一メーカー内で名称類似度順→残りはメーカー跨ぎ（形態一致優先）で決定。
  メーカー跨ぎの更新とⒸ既設マーク付き更新は「質問」列に要確認と自動記載。
- 更新行は台帳の「例」シートの慣例に従い、**赤文字・前装置転記・TYPE/主目的は空白+黄色塗り**。
  システム名・メーカー名はシート内の既存表記に自動で合わせる（例: PDF「Azurion 7 B12」→
  Excel慣例「Azurion7 B12」）。
- PDFにあるがExcelに行が無い装置は「質問」列に記載（**行追加はしない**）。
  PDFにあるがExcelに無い病院もレポートのみ。
- 最後に「対象行 = 変更なし + 更新 + 未掲載」の恒等式をassertし、全変更をレポート出力する。

## Step 3: 検証と報告

1. レポートの更新行を出力Excelで開いて目視し、特に「[要確認]」の行はPDF画像と再照合する。
2. PDFの装置数と「変更なし+更新+PDFのみ+新病院」の合計が一致するか数える。
   ずれていればStep 1の転記漏れなので、該当列の画像を読み直す。
3. ユーザーへの報告には必ず含める: 変更なし/更新/未掲載の行数内訳、質問列に残した要確認事項の
   一覧、**行追加していないPDFのみの装置・病院**（追加するかユーザーに確認する）。
4. 元Excelに「例」シートがあり本スキルの手順と矛盾する場合は「例」シートを優先する。

注意:

- openpyxlの保存時に「Data Validation extension is not supported」警告が出るが既知の挙動
  （ドロップダウン入力規則の一部が落ちる）。ユーザーに一言添える。
- 出力は必ず元ファイルと別名で保存して提示する。元ファイルは変更しない。
- 「全欄が埋まった美しい表」より「曖昧さが質問列に可視化された正直な表」が正しい納品物である。
