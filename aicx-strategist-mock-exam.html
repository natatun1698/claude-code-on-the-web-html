Chapter 1: 生成AIとAIエージェントの基礎(問1〜8)

問1定義理解

中堅商社A社は、FAQに定型文を返すチャットボットを導入し「わが社もAIエージェントを導入済みだ」と説明している。この認識に対する評価として最も適切なものはどれか。

  1. FAQに自動応答している時点でAIエージェントと呼んで差し支えない
  2. 定型応答のみでは自律的な計画立案やツール実行を伴わないため、AIエージェントとは言い難い
  3. 生成AIを使っていればすべてAIエージェントに分類される
  4. チャット形式のUIを持つシステムはすべてAIエージェントである
解答・解説
正解: B — AIエージェントの要件は「目標に対して自律的に計画し、ツールを使い、状況を判断しながらタスクを遂行する」こと。定型応答ボットは生成AI活用ではあってもエージェントの自律性要件を満たさない。定義の線引きは第1章の最頻出論点。
問2自律性レベル

B社経理部では、AIが請求書データから仕訳の下書きを作成し、担当者が内容を確認・承認した後に会計システムへ登録される運用を行っている。この自動化の形態として最も適切なものはどれか。

  1. 完全自律型(人間の関与なし)
  2. Human-in-the-Loop型(人間の承認を組み込んだ半自動化)
  3. 手動業務(自動化されていない)
  4. Human-out-of-the-Loop型(人間は事後監査のみ)
解答・解説
正解: B — 実行前に人間の確認・承認ステップが組み込まれているためHuman-in-the-Loop(HITL)。会計処理のような誤りが金銭的損害に直結する業務では、HITLの配置が定石とされる。
問3起動タイプ

C社は「顧客からの問い合わせフォーム送信を検知したら、内容を分類してCRMに起票する」エージェントを設計したい。この場合の起動タイプとして最も適切なものはどれか。

  1. スケジュール起動(毎時実行)
  2. ユーザー起動(担当者がチャットで依頼)
  3. イベント起動(フォーム送信をトリガーに実行)
  4. 常時起動(無限ループで待機)
解答・解説
正解: C — 特定の出来事(フォーム送信)を契機に処理を開始するためイベント起動が適切。スケジュール起動は「毎朝8時に日次レポート作成」のような定時処理に向く。起動タイプ3類型(ユーザー/スケジュール/イベント)の適用判断はケース問題の定番。
問4RAG適用

D社の社内ヘルプデスクAIは、就業規則について質問すると一般論や古い情報を回答してしまう。改善策として最も適切なものはどれか。

  1. より大きなパラメータ数のLLMに変更する
  2. RAGを導入し、最新の社内規程文書を検索して回答の根拠として参照させる
  3. プロンプトに「正確に答えてください」と追記する
  4. 回答の文字数を制限する
解答・解説
正解: B — LLMは学習データにない社内固有情報を知らないため、RAG(検索拡張生成)で社内文書を都度参照させるのが正攻法。モデルサイズ変更やプロンプトの精神論では社内情報は取得できない。
問5MCP★必出

E社はAIエージェントをCRM、カレンダー、社内データベースなど複数の外部ツールに接続したいが、ツールごとに個別のカスタム連携を開発すると保守コストが膨らむと懸念している。この課題に対する標準的なアプローチとして最も適切なものはどれか。

  1. すべてのツールのデータを1つのExcelに集約してAIに読み込ませる
  2. MCP(Model Context Protocol)のような標準プロトコルを介してツールを接続し、連携実装を共通化する
  3. ツールごとに別々のAIエージェントを開発する
  4. 外部ツール連携は諦め、AIには文章生成のみをさせる
解答・解説
正解: B — MCPはAIモデルと外部ツール・データソースの接続を標準化するオープンプロトコル。個別実装の乱立(M個のAI×N個のツール=M×N通りの開発)を避け、共通規格で接続できる。「AI界のUSB-C」という比喩で説明されることが多い。
問6MCP★必出

F社は在庫管理システム(リアルタイムに更新される構造化データベース)の情報をAIエージェントに扱わせたい。最も適切なデータ接続方式はどれか。

  1. データベース全件を定期的に文書化してRAGのナレッジベースに登録する
  2. MCP経由でデータベースに接続し、必要なデータをその都度問い合わせる
  3. 在庫データをすべてプロンプトに貼り付ける
  4. LLMをファインチューニングして在庫数を記憶させる
解答・解説
正解: B — リアルタイム性が求められる構造化データは、ナレッジベース化(RAG)すると鮮度が失われる。MCP等でDBに直接問い合わせるのが適切。受験者の学習メモにも「データベース(構造化データ)はナレッジベースではなくMCPで必要な分を問い合わせるが吉」とある通り、RAGとMCPの使い分けは最重要論点。
問7MCP★必出

MCPを導入する利点の説明として最も適切なものはどれか。

  1. LLM自体の推論精度が向上する
  2. AIと外部ツールの統合を標準化し、接続実装の重複開発を削減できる
  3. ハルシネーションが完全になくなる
  4. ネットワーク通信が不要になる
解答・解説
正解: B — MCPは「接続の標準化」の技術であり、モデルの賢さやハルシネーションそのものを解決するものではない。誤答A・Cのような「MCPを万能視する選択肢」がひっかけとして置かれる可能性が高い。
問8ハルシネーション

G社の法務相談AIが、実在しない条文番号を挙げて回答する事象が報告された。対策として最も適切なものはどれか。

  1. プロンプトに「嘘をつかないでください」と指示する
  2. RAGで法令・社内規程の原文を参照させ、回答に出典の提示を必須化した上で、重要判断には人間のレビューを組み込む
  3. AIの回答をそのまま社外に送付してよいことにする
  4. 生成の多様性(temperature)を上げて別の回答を引き出す
解答・解説
正解: B — ハルシネーション対策の基本は「根拠データの参照(RAG)+出典明示+高リスク箇所への人間の検証」の組み合わせ。指示文だけで防げるものではなく、temperatureを上げるのは逆効果。

Chapter 2: 業務の基礎(問9〜14)

問9As-Is/To-Be

H社のDX担当者は「話題のAIエージェントツールをまず契約し、使いながら適用先を探そう」と提案している。ストラテジストとしての助言で最も適切なものはどれか。

  1. ツール導入が先。触らないと何も分からない
  2. まず現状業務(As-Is)を可視化・棚卸しし、あるべき姿(To-Be)とのギャップから適用領域を特定した上でツールを選定すべき
  3. 他社が使っているツールをそのまま導入すれば失敗しない
  4. To-Beを描く必要はなく、As-Is分析だけで十分である
解答・解説
正解: B — 「ツールから入る」のは典型的な失敗パターン。As-Is可視化→To-Be設計→ギャップ分析→手段選定の順序が原則。この「手順の正しさ」を問う問題は頻出が予想される。
問10ECRS

I社の経費精算は5段階の承認を要し、担当者から「この承認フローをAIで自動化してほしい」と要望が出た。ECRS原則に基づく検討の進め方として最も適切なものはどれか。

  1. 5段階承認をそのままAIで再現し高速化する
  2. まず各承認ステップの必要性を疑い、廃止(Eliminate)できる工程がないかを最初に検討する
  3. 承認者を増やして統制を強化する
  4. いきなりシステムを刷新(Rearrange)する
解答・解説
正解: B — ECRSはEliminate(排除)→Combine(結合)→Rearrange(再配置)→Simplify(簡素化)の順に検討する。「ムダな業務をそのまま自動化する」のは最悪手であり、E(排除)を最初に検討するのが原則。ECRSの適用順序は最頻出論点の一つ。
問11【WS】IPO

公式実践ワークシートの業務棚卸しでは、対象業務を「何を受け取り(Input)、どう処理し(Process)、何を出すか(Output)」に分解して記述する。この分解を行う主な目的として最も適切なものはどれか。

  1. 業務担当者の人事評価を行うため
  2. 業務の構造を形式知化し、AIに任せられる工程と人間が担う工程の切り分けを可能にするため
  3. 提出書類の枚数を増やすため
  4. ITベンダーへの発注金額を算出するため
解答・解説
正解: B — IPO分解の狙いは、曖昧な「仕事のかたまり」を入出力の明確な工程に構造化し、自動化適性を判断できる単位にすること。ワークシートの「何のためにこの欄を書くのか」を問う出題が予想される。
問12可視化手法

J社では受注処理が営業→審査→物流と3部門をまたぎ、部門間の受け渡しで滞留が発生しているらしい。ボトルネックの特定に最も適した可視化手法はどれか。

  1. 組織図
  2. スイムレーン図(部門別レーンで業務フローを描く)
  3. 円グラフ
  4. ガントチャート
解答・解説
正解: B — スイムレーン図は「誰(どの部門)が」「どの順で」処理するかを可視化でき、部門間の受け渡し(ハンドオフ)の滞留を発見するのに最適。手法名と用途の対応付けは知識問題として出やすい。
問13HTA

K社のベテラン審査担当者の業務は「一見1つの判断」に見えるが、実際には複数の下位判断の積み重ねで構成されている。この業務をAI適用のために分解する手法として最も適切なものはどれか。

  1. HTA(階層的タスク分析)で上位タスクを下位タスクへ段階的に分解する
  2. SWOT分析で強み・弱みを整理する
  3. 3C分析で市場を分析する
  4. ブレインストーミングで自由にアイデアを出す
解答・解説
正解: A — HTA(Hierarchical Task Analysis)は複雑な業務を階層的に分解する手法で、「どの下位タスクならAIに任せられるか」の判断材料を作れる。SWOTや3Cは経営分析フレームワークであり業務分解には使わない。
問14暗黙知

L社では長年の経験で判断してきたベテラン社員が半年後に退職する。この業務にAIエージェントを導入する準備として最も適切な最初の行動はどれか。

  1. 退職後にAIに過去データから判断基準を推測させる
  2. 在職中にヒアリング等を行い、判断基準・例外対応を言語化して暗黙知を形式知化する
  3. 業務マニュアルは作らずAIツールだけ先に契約する
  4. ベテランの画面操作を録画しておけば十分である
解答・解説
正解: B — AIエージェント設計の前提は業務知識の形式知化。特に「なぜそう判断するのか」という基準・例外パターンは録画やログからは復元困難で、在職中の言語化が不可欠。「暗黙知の形式知化」はこの資格の3大スキル軸(業務設計)の中核。

Chapter 3: AIデータリテラシーとマネジメント(問15〜20)

問15データ分類

M社が保有する「顧客マスタ(データベースの表形式データ)」と「顧客からのクレームメール(自由記述)」の分類として正しい組み合わせはどれか。

  1. 両方とも構造化データ
  2. 顧客マスタ=構造化データ、クレームメール=非構造化データ
  3. 顧客マスタ=非構造化データ、クレームメール=構造化データ
  4. 両方とも非構造化データ
解答・解説
正解: B — 行と列で定義された表形式データは構造化データ、自由記述の文章・画像・音声は非構造化データ。生成AIは非構造化データの処理を得意とする一方、構造化データはDB問い合わせ(MCP経由等)で扱うのが基本、という接続論点も併せて押さえたい。
問16RAGの仕組み

RAGの処理の流れとして最も適切なものはどれか。

  1. 質問受付→LLMが回答生成→生成後に文書を検索して答え合わせ
  2. 質問受付→関連文書を検索→検索結果をコンテキストとして付与→LLMが回答生成
  3. 全社文書でLLMを再学習→質問受付→回答生成
  4. 質問受付→人間が文書を探して貼り付け→回答生成
解答・解説
正解: B — RAGは「検索(Retrieval)で関連文書を取得→生成(Generation)の入力に加える」の順。ファインチューニング(再学習)とは別物という区別も頻出。
問17ナレッジ運用

N社の社内規程AIは、3ヶ月前に改定された規程の古い内容を回答し続けている。根本的な対策として最も適切なものはどれか。

  1. ユーザーに「回答は古い可能性があります」と注意書きを出すだけにする
  2. ナレッジベースの更新プロセスと更新責任者(オーナー)を定め、規程改定と連動して反映される運用を整備する
  3. AIの利用を禁止する
  4. 改定のたびにAIシステム全体を作り直す
解答・解説
正解: B — RAGは「参照するデータの鮮度」がすべて。データオーナーと更新フローを定める「運用設計」まで含めて初めて実装と言える、というのがこの試験の思想。注意書きだけの対症療法(A)はひっかけ。
問18ガバナンス

O社の社内AIアシスタントに一般社員が「役員の報酬額を教えて」と質問すると回答してしまうことが判明した。対策として最も適切なものはどれか。

  1. 該当の質問文をブラックリストに登録する
  2. ナレッジソースへのアクセス権限を利用者の役割(ロール)に応じて制御する仕組みを導入する
  3. AIに「機密情報は答えないで」とプロンプトで頼む
  4. 役員報酬データを紙にして保管する
解答・解説
正解: B — 質問文のブラックリストやプロンプト指示は言い換えで容易に回避される。データソース側のアクセス制御(ロールベース)で「そもそも見せない」のが正攻法。データガバナンスは第3章の重要論点。
問19個人情報

P社は顧客の氏名・住所を含む問い合わせデータを外部の生成AIサービスで処理しようとしている。事前の対応として最も適切なものはどれか。

  1. 顧客データなので何の確認もなくそのまま入力してよい
  2. サービスの利用規約(入力データの学習利用有無等)を確認し、必要に応じて個人情報のマスキング・最小化を行い、社内規程・法令に沿った利用とする
  3. 個人情報保護法はAIには適用されないので気にしない
  4. 担当者個人の無料アカウントで処理すれば会社の責任にならない
解答・解説
正解: B — 外部AIサービス利用時は「入力データがどう扱われるか」の確認と、個人データの最小化・マスキングが基本動作。個人の無料アカウント利用(D)はシャドーAIの典型でむしろリスク増。
問20データ品質

Q社のAIエージェントの回答精度が低い。調査の結果、参照元データに重複・旧版・誤記が大量に混在していた。優先すべき対応はどれか。

  1. より高性能なLLMに乗り換える
  2. 参照元データの整備(重複排除・最新化・正誤確認)を先に行う
  3. プロンプトを長くする
  4. 回答速度を上げる
解答・解説
正解: B — 「Garbage In, Garbage Out」。データ品質の問題はモデル変更では解決しない。原因がデータにあると特定できているのにモデルに手を出す選択肢は典型的ひっかけ。

Chapter 4: 自動化レベルとワークフロー設計(問21〜28)

問21【WS】自動化適性

公式ワークシートの自動化適性評価の観点で、R社の次の4業務のうち、最初のAIエージェント適用対象として最も適切なものはどれか。

  1. 年1回だけ発生する、経営判断を伴う中期計画策定
  2. 毎日大量に発生し、判断ルールが明確で、例外が少ない請求書データ入力・照合
  3. 個別交渉が中心で相手の感情への配慮が成否を分けるクレーム最終対応
  4. 担当者ごとにやり方が異なり手順が言語化されていない業務
解答・解説
正解: B — 自動化適性は「頻度が高い×ルールが明確×例外が少ない」で評価するのが定石。頻度が低い(A)、感情対応(C)、形式知化未了(D)はいずれも初期対象に不適。ワークシートのスコアリング観点そのものを問う形式が予想される。
問22HITL配置

S社は取引先への自動送金までを行う経理エージェントを設計中である。Human-in-the-Loop(人間の承認)を配置すべき箇所として最も適切なものはどれか。

  1. 請求書PDFの文字読み取りの直後
  2. 送金実行の直前(不可逆かつ金銭リスクの高い操作の前)
  3. 処理完了メールの送信後
  4. 人間の承認は一切不要である
解答・解説
正解: B — HITLは「すべての工程」ではなく「不可逆・高リスクな意思決定点」に置くのが設計原則。全工程に人を挟むと自動化の意味がなく、ゼロにするとリスク管理が破綻する。「どこに人間の検問を置くか」は受験者ブログでも核心と指摘される最重要論点。
問23トリガー設計

「問い合わせメールを受信したら、内容を分類し、CRMに起票し、担当者を割り当てる」というワークフローにおける「トリガー」はどれか。

  1. 内容の分類
  2. 問い合わせメールの受信
  3. CRMへの起票
  4. 担当者の割り当て
解答・解説
正解: B — トリガーはワークフローを開始させる契機となる事象。分類・起票・割当はいずれもトリガー後に実行される「アクション」。トリガーとアクションの識別は基本問題として出やすい。
問24コンテキスト設計

T社のエージェントは同じ依頼でも回答品質がばらつく。原因は業務前提(用語定義・手順・判断基準)が十分に与えられていないことにある。改善アプローチとして最も適切なものはどれか。

  1. 思いつく情報をすべて無秩序にプロンプトへ貼り付ける
  2. 業務に必要な文脈(定義・手順・判断基準・良い例)を構造化して与えるコンテキストエンジニアリングを行う
  3. AIが空気を読むまで待つ
  4. 回答が安定するまで同じ質問を繰り返す
解答・解説
正解: B — コンテキストエンジニアリングは「必要な情報を、必要な形で、過不足なく」与える設計技術。「大量に貼れば良い」(A)は文脈の希釈やコスト増を招く誤答として置かれやすい。
問25例外設計

U社のエージェントは外部システムの障害時に処理が失敗するが、そのまま何事もなかったかのように次の処理へ進んでしまう。ワークフロー設計の改善として最も適切なものはどれか。

  1. 失敗は無視して処理を続行する現状のままでよい
  2. エラーを検知したら処理を保留し、人間へエスカレーションするフォールバック経路を設計する
  3. 成功するまで無制限にリトライさせる
  4. 障害が起きないよう祈る
解答・解説
正解: B — 正常系だけでなく異常系(エラー検知→保留→人間へのエスカレーション)まで設計して初めてワークフロー設計と言える。無制限リトライ(C)は障害を拡大させ得る。
問26適用限界

V社は解約を申し出た顧客への引き止め対応を完全自動化しようとしている。ストラテジストの判断として最も適切なものはどれか。

  1. 感情面の配慮が成否を左右する対応であり、情報収集や下準備はAIが支援しつつ、対話自体は人間が担う設計とする
  2. すべてAIに任せ、人件費を最大限削減する
  3. AIには何もさせず、従来通りすべて人間が行う
  4. 解約対応という業務自体を廃止する
解答・解説
正解: A — 「全自動 or 全手動」の二者択一ではなく、AIと人間の役割分担を設計するのがストラテジストの仕事。実務未経験者は「全自動化」か「AIには無理」の両極端に振れやすいと指摘されており、中庸の分担設計が正解になるパターンが多いと予想される。
問27工程分割

W社は「受注から出荷まで全業務を1つの巨大エージェントに任せる」構成で開発したが、動作が不安定で原因調査も困難になっている。改善方針として最も適切なものはどれか。

  2. 業務を工程単位に分割し、各エージェントの責務を明確にした上で連携させる構成に見直す
  3. プロンプトを10倍の長さにする
  4. 不安定なまま本番運用を続ける
解答・解説
正解: B — 責務が肥大化したエージェントは精度低下・デバッグ困難を招く。工程分割(単一責務化)と連携設計が原則で、これはワークフロー設計の章の中核的な考え方。
問28MCP×権限★必出

X社のエージェントは経費データの「参照」しか必要としないのに、MCPサーバー経由で基幹データベース全体への書き込み権限まで付与されている。この状態の評価として最も適切なものはどれか。

  2. 最小権限の原則に反しており、誤動作や悪用時の被害が拡大するため、必要最小限(該当データの読み取りのみ)に絞るべき
  3. AIは間違えないので権限管理は不要
  4. 書き込み権限があると読み取り速度が上がるので合理的
解答・解説
正解: B — エージェントに与えるツール・権限は「タスク遂行に必要な最小限」が原則。エージェントが自律的に行動する分、過剰権限のリスクは従来システムより大きい。MCP実装面とガバナンスを絡めた複合問題が予想される。

Chapter 5: 人と組織の設計(問29〜34)

問29推進体制

Y社では各部署が個別バラバラにAIツールを導入し、ノウハウが分散し重複投資も発生している。全社的な品質・ガバナンスを確保しつつ現場の自律性も活かす推進体制として最も適切なものはどれか。

  1. 完全中央集権型: 情報システム部門がすべてのAI活用を代行する
  2. 完全分散型: 現状通り各部署の自由に任せる
  3. CoE型: 全社横断のセンターオブエクセレンスが標準・ガバナンス・支援を担い、実行は各部署が行う
  4. 外部委託型: すべてコンサルタントに丸投げする
解答・解説
正解: C — 中央集権型は統制は効くがスピードと現場適合性を欠き、分散型は速いが品質・ガバナンスが崩れる。両者のバランスを取るCoE型が「標準化×現場自律」の両立解として提示されるのが定番。3類型の長所短所の比較は頻出予想。
問30チェンジマネジメント

Z社でAIエージェント導入を発表したところ、ベテラン社員から「自分たちの仕事を奪う気か」と強い反発が起きた。対応として最も適切なものはどれか。

  1. 反対意見は無視してトップダウンで強行する
  2. 反発した社員を導入プロジェクトから外す
  3. 導入目的(付加価値業務へのシフト等)を丁寧に説明し、ベテランを設計段階から巻き込み、小さな成功体験を共有しながら段階的に進める
  4. 導入自体を取りやめる
解答・解説
正解: C — チェンジマネジメントの原則は「早期の巻き込み」「目的の共有」「スモールウィン」。強行(A)や排除(B)は抵抗を潜在化させ定着を阻む。「反対派への動き方」は実務未経験者が判断を誤りやすい領域と指摘されており、出題確度が高い。
問31役割再設計

AIエージェント導入で事務作業が月100時間削減された部署について、経営層から「その分の人員を削減すべきか」と問われた。ストラテジストの提言として最も適切なものはどれか。

  1. 削減時間=不要人員として即座にリストラを提案する
  2. 創出された時間を顧客対応・改善活動など付加価値業務へ再配分する役割再設計と、それに合わせた評価指標の見直しを提案する
  3. 浮いた時間の使途は各自の自由とし、何も設計しない
  4. 削減効果を経営層には報告しない
解答・解説
正解: B — この資格が掲げる組織設計スキルは「AIとの協働を前提とした役割・評価の再設計」。削減時間の使途を設計しないと効果が霧散し、安易な人員削減はチェンジマネジメント全体を崩壊させる。
問32現場巻き込み

AA社では情報システム部門だけでAIエージェントのPoCを完了しリリースしたが、現場は「実際の業務と合わない」と使わず、利用率が低迷している。根本原因として最も適切なものはどれか。

  1. AIの性能が低かった
  2. 業務の実態を知る現場ユーザーを要件定義・設計段階から参画させなかった
  3. リリース告知のメールが短かった
  4. 現場社員のITリテラシーが低い
解答・解説
正解: B — 「作ったのに使われない」の典型原因は現場不在の設計。ユーザー巻き込みは5DモデルのDiscovery/Definition段階からの必須要素であり、原因帰属を現場のせい(D)にする選択肢はひっかけ。
問33シャドーAI

BB社で、従業員が会社非公認の無料生成AIサービスに顧客情報を入力していたことが発覚した。対応として最も適切なものはどれか。

  2. 利用ガイドラインを整備し、安全に使える公認のAI環境を提供した上で、リスク教育を行う
  3. 発覚した従業員を処分すれば再発しない
  4. 問題が公にならなければ放置する
解答・解説
正解: B — 全面禁止はシャドーAI(非公認利用)を地下化させるだけで、リスクはむしろ増大する。「安全な公式手段の提供+ルール+教育」のセットが定石。
問34説明責任

CC社の経営会議でAIエージェント投資の承認を得るための説明として最も適切なものはどれか。

  1. 「AIは時代の流れなのでとにかくやるべきです」と熱意を伝える

問355D順序

AIエージェント実装の5Dモデルの正しい順序はどれか。

  4. KPIの達成度評価レポート作成
解答・解説
正解: B — Discoveryは「どこに機会があるか」を発見するフェーズで、公式ワークシートによる業務棚卸しはここに対応する。フェーズと活動・ワークシートの対応を問う問題は、ワークシート出題の本命パターン。
問37Definition

DD社はAIエージェント開発に着手しようとしているが、「成功とは何か」が定義されていない。Definitionフェーズで行うべきこととして最も適切なものはどれか。

  2. 処理時間・エラー率・利用率など測定可能なKPIと目標値を、開発着手前に定義する
  3. 「なんとなく便利になった」という感覚で評価することにする
  4. KPIは導入後1年経ってから設定する
解答・解説

問38Design

Designフェーズのワークフロー設計書に必ず含めるべき要素として最も適切なものはどれか。

  4. 完成後の打ち上げの計画
解答・解説
正解: B — 設計の核心は人間とAIの役割分担(どこにHITLを置くか、例外は誰が拾うか)の明文化。トリガー・アクション・フォールバックとセットで設計書に落とす。
問39Development

EE社は初のAIエージェントを、いきなり全社3,000人に展開しようとしている。Developmentフェーズの進め方として最も適切なものはどれか。

  1. 予定通り全社一斉展開する
  2. 限定した部署・業務範囲でPoC(概念実証)を行い、KPIで効果検証・改善した上で段階的に拡大する
  3. PoCを5年間続けて本番展開はしない
  4. 開発を外部委託したらテストせずリリースする

正解: B — スモールスタート→検証→改善→段階拡大が原則。一方で「PoC止まり(PoC疲れ)」も失敗パターンであり、検証後に拡大まで進める設計が問われる。両極端(A・C)が誤答として並ぶ構図が予想される。
問40Deployment

FF社はエージェントを本番リリースした。Deploymentフェーズにおけるその後の対応として最も適切なものはどれか。

  1. リリースしたのでプロジェクトは完了。あとは放置する
  2. 利用率・精度・エラー率をモニタリングし、現場フィードバックを収集して改善サイクルを回し、業務への定着を図る

MCP(Model Context Protocol)の説明として最も適切なものはどれか。

  1. 2024年にAnthropicが公開した、AIモデルと外部ツール・データソースの接続を標準化するオープンプロトコルで、その後業界の主要各社にも採用が広がった
  2. 特定のベンダーの製品でのみ利用できる独自規格である
  3. LLMの学習(トレーニング)を高速化するためのプロトコルである
  4. 人間同士のビデオ会議のための通信規格である
解答・解説
正解: A — MCPは2024年11月にAnthropicがオープンソースで公開した接続標準。OpenAI、Google、Microsoftなど主要各社が相次いで対応を表明し、エージェント接続のデファクトスタンダードとなった。「オープンな標準規格である」点が独自規格(B)との対比で問われやすい。
問42A2A

2025年にGoogleが発表した「A2A(Agent2Agent)」プロトコルの目的として最も適切なものはどれか。

  1. AIエージェント同士が相互に通信・連携するための標準を定めること
  2. MCPを置き換えて廃止させること
  3. 人間の脳とAIを直接接続すること
  4. 画像生成の画質を向上させること
解答・解説
正解: A — A2Aはエージェント間連携のプロトコル。「MCPはエージェント↔ツール/データの接続、A2Aはエージェント↔エージェントの連携」という補完関係で説明されることが多く、両者の役割の違いを問う問題は時事の本命。
問43EU AI Act

EUのAI規制法(EU AI Act)の特徴として最も適切なものはどれか。

  1. すべてのAIを一律に禁止する法律である
  2. AIをリスクの大きさで分類し、許容できないリスクのAIは禁止、高リスクAIには厳格な義務を課す「リスクベースアプローチ」を採る
  3. EU域内の企業にのみ適用され、日本企業には一切関係がない
  4. 罰則のない自主的ガイドラインである
解答・解説
正解: B — 2024年に成立した世界初の包括的AI規制法で、リスクベースアプローチが最大の特徴。禁止AI規定は2025年2月、汎用AI(GPAI)への義務は2025年8月から段階適用。EU市場に製品・サービスを出す日本企業にも域外適用があり得る点(Cの否定)も重要。
問44日本のAI法

2025年に日本で成立した「AI推進法(人工知能関連技術の研究開発及び活用の推進に関する法律)」の性格として最も適切なものはどれか。

  1. EUのAI Actと同様の罰則付き規制法である
  2. AIの研究開発・活用の推進を基本理念とし、罰則を設けないイノベーション促進型の基本法である
  3. 生成AIの利用を国民に義務付ける法律である
  4. AIに法人格を与える法律である
解答・解説
正解: B — 日本初のAIに関する基本法で、規制より推進に軸足を置き、直接罰則を持たない点がEU型との対比で語られる。内閣にAI戦略本部を設置。「日本=ソフトロー中心、EU=ハードロー」という国際比較は時事問題の定番構図。
問45AI事業者ガイドライン

日本の「AI事業者ガイドライン」(総務省・経済産業省)の説明として最も適切なものはどれか。

  1. AI開発企業だけを対象とした技術仕様書である
  2. AIの主体を「開発者」「提供者」「利用者」に分け、それぞれが取り組むべき事項を示した統合的なガイドラインである
  3. 違反すると刑事罰が科される法律である
  4. 個人のスマートフォン利用時間を制限する指針である
解答・解説
正解: B — 従来の複数ガイドラインを統合し2024年に公表(以後改訂を重ねる)。開発者/提供者/利用者の3主体別に「人間中心」「安全性」「公平性」等の指針を整理。企業がAIエージェントを「利用する側」としても対象になる点が実務上のポイント。
問46国際枠組み

「広島AIプロセス」の説明として最も適切なものはどれか。

  1. 広島県内限定のAI導入補助金制度
  2. G7が合意した、高度なAIシステムに関する国際指針・行動規範を策定する国際的な枠組み
  3. AIによる核軍縮交渉プログラム
  4. 特定企業の社内研修プログラム
解答・解説
正解: B — 2023年のG7広島サミットを契機に日本が主導した国際枠組みで、開発者向け国際指針・行動規範を策定。日本発の国際ルール形成の事例として時事で扱われやすい。
問47著作権

文化庁「AIと著作権に関する考え方」における整理として最も適切なものはどれか。

  1. AIの学習に著作物を使うことは、どんな場合でも著作権侵害となる
  2. AI学習は原則として著作権法30条の4により許容され得るが、生成物が既存著作物と類似性・依拠性を持つ場合は通常の著作権侵害となり得る
  3. AIが生成したものはすべて著作権フリーで商用利用に何の制約もない
  4. AI生成物の著作権はすべてAI開発企業に帰属する
解答・解説
正解: B — 「学習段階は原則適法となり得る(30条の4)」「生成・利用段階は通常の侵害判断(類似性+依拠性)」という2段階の整理が核心。企業でAIエージェントに文書・画像を生成させる際の実務リスクとして問われやすい。
問48AIMS規格

  1. AIマネジメントシステム(AIMS)に関する国際規格で、組織がAIを責任をもって開発・利用するための管理体制の要求事項を定める
  2. Wi-Fiの通信速度に関する規格である

正解: A — 2023年末に発行された世界初のAIマネジメントシステム国際規格。ISMS(27001)のAI版と説明されることが多く、国内でも認証取得企業が増加中。組織的なAIガバナンス強化の文脈で時事に載りやすい。
問49セキュリティ

AIエージェント特有のセキュリティリスク「プロンプトインジェクション」の説明として最も適切なものはどれか。

  1. 外部から読み込ませた文書やWebページ等に埋め込まれた悪意ある指示によって、エージェントが本来の指示から逸脱した動作(情報漏えい等)をさせられる攻撃
  2. プロンプトを注射器でサーバーに物理的に注入する攻撃

問51エージェント動向

問52個人情報×生成AI

  1. 個人データを本人の同意なく、応答目的以外(サービスの学習等)に利用されうる形で入力しないよう留意が必要である
  2. 生成AIには個人情報保護法が一切適用されない
  3. 顧客の個人データは自由に入力してよい

5. 学習アドバイス

  • 公式テキストは「暗記」ではなく「自社に当てはめて」読む — 公式自身が「業務への当てはめが暗記との差を生む」と明示。各章のフレームワーク(ECRS、IPO、5D、CoE)を自分の業務で1回ずつ言語化してみるのが最短ルート。
  • ワークシートは実際に1枚書いてみる — 「どの欄に何を書くか」「その欄は何のためにあるか」が問われると想定。眺めるだけでなく手を動かす。
  • MCPは3点セットで整理 — ①何を標準化するのか(ツール接続) ②RAGとの使い分け(非構造化ナレッジ=RAG/構造化・リアルタイム=MCP問い合わせ) ③権限・セキュリティ(最小権限、プロンプトインジェクション)。
  • 時事は「プロトコル動向+法規制」の2軸 — MCP/A2A、EU AI Act、日本のAI推進法・AI事業者ガイドライン、著作権、ISO/IEC 42001あたりを直近ニュースとともに確認。
  • 選択肢の絞り方 — 「理想論すぎる」「全自動/全禁止の両極端」「原因をモデルのせいにする」「人を無視する」選択肢は誤答であることが多い、というメタ戦略が有効と分析されている。
